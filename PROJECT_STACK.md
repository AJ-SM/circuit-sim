# circuit-sim (NETSCOPE): Complete Project Stack

Everything this project uses: languages, frameworks, libraries, AI models, external tools, APIs, configuration and files. The project has two halves. A **Python/FastAPI backend** recognises circuits in images and runs simulations. A **React/TypeScript frontend** is the schematic editor, called "NETSCOPE".

```
Hand drawing / photo ──► Frontend (React) ──► POST /generate-circuit ──► YOLO + OpenCV + OCR ──► netlist JSON
Schematic on canvas  ──► Frontend (React) ──► POST /simulate         ──► SPICE deck ──► ngspice ──► voltages / currents
```

## 2. Backend (`backend/`)

### 2.1 Framework and server

| Item | Purpose |
|---|---|
| **FastAPI** | Web framework. All routes are in `main.py` |
| **Uvicorn** (`uvicorn[standard]`) | ASGI server: `python -m uvicorn main:app --port 8000` |

| **CORSMiddleware** | Allows any origin (`allow_origins=["*"]`) for local development |
| Background thread | Warms the YOLO and OCR models up at startup |

| Package | Required? | Used for |
|---|---|---|
| `fastapi` | Yes | API framework |

| `ultralytics` | Yes | Runs the YOLO detection model. Also installs **PyTorch**, **torchvision**, **Pillow** and **PyYAML** |

| `transformers` | Optional | **TrOCR** handwriting model, used as a second reading of each value |
| `sentencepiece` | Optional | Tokenizer support for TrOCR |
| `onnxruntime` | Optional | Faster CPU inference for the CRAFT text detector |
| `onnx` | Optional | Exports CRAFT to ONNX once and caches it |
| `torch` (via ultralytics) | Yes, indirectly | Model inference backend |
| `Pillow` (`PIL`) | Yes, indirectly | Image handling for TrOCR |

### 2.3 Python standard library modules

`os`, `sys`, `re`, `json`, `math`, `random`, `base64`, `binascii`, `tempfile`, `subprocess` (runs ngspice), `threading` (model lock and warm-up), `pathlib`, `dataclasses`, `typing`, `datetime`, `urllib.request`.

### 2.4 External programs

| Tool | Purpose |
|---|---|
| **ngspice** | SPICE circuit simulator. Runs in batch mode (`ngspice -b`) with a 30 s timeout. The backend looks for `NGSPICE_PATH`, then `ngspice_con` (Windows/Chocolatey), then `ngspice` |

### 2.5 Backend files

| File | Role |
|---|---|
| `main.py` | FastAPI app. Builds the SPICE deck, runs ngspice, parses results, computes per-branch analysis |
| `recognizer.py` | Image to netlist pipeline. Loads YOLO, detects at 0° and ±45° rotations, merges detections, renames parts |
| `drawn_topology.py` | Ink-based connectivity engine: finds pins, wires and nets from the drawing, and source polarity |
| `value_reader.py` | OCR of component values and designators (easyocr + TrOCR), unit parsing, SPICE formatting |
| `check_solver_polarity.py` | Test/audit script. Checks branch-current signs against a numpy MNA solve, Ohm's law, KCL and power balance |
| `model/wire_detector.py` | Wire segment, junction and endpoint detection (skeletonisation) |
| `model/terminal_extractor.py` | Component pin and terminal extraction from bounding boxes |
| `model/connectivity_graph.py` | Builds nets from pins and wires |
| `model/netlist_generator.py` | Produces the final netlist and SPICE lines |
| `model/circuit_detector_v2_best.pt` | YOLO weights v2 (9 classes, hand-drawn fine-tune) |
| `model/circuit_detector_best.pt` | YOLO weights v1 (8 classes) |
| `README.md`, `BACKEND_SUMMARY.md` | Backend documentation |

### 2.6 API endpoints

| Method | Route | Purpose |
|---|---|---|
| `GET` | `/health` | Liveness check. Returns `{"status":"ok"}` |
| `POST` | `/simulate` | Netlist JSON to ngspice. Returns node voltages, branch currents and branch analysis |
| `POST` | `/detect-components` | Base64 image to YOLO detections (boxes, classes, confidences) |
| `POST` | `/generate-circuit` | Base64 image (optionally with edited detections) to a full netlist JSON |
| `GET` | `/docs` | Swagger UI that FastAPI generates automatically |

### 2.7 SPICE component mapping

| Frontend type | SPICE line |
|---|---|
| `resistor` | `R n1 n2 <resistance>` |
| `capacitor` | `C n1 n2 <capacitance>` |
| `inductor` | `L n1 n2 <inductance>` |
| `vsource_dc` / `battery` | `V n1 n2 DC <voltage>` |
| `vsource_ac` | `V n1 n2 AC <V> SIN(0 V f)` |
| `ground` | Node `0` marker only |

Analysis run: DC operating point (`.op`).

## 3. AI / Machine Learning

### 3.1 Component detector

| Item | Detail |
|---|---|
| Model | **YOLOv12n** (nano), Ultralytics 8.4.x |
| Starting point | COCO-pretrained `yolo12n.pt` |
| Task | Object detection (bounding box + class for each symbol) |
| Inference | `conf = 0.25`, `iou = 0.45`, plus extra passes on images rotated ±45° |
| Training data | Roboflow *Hand Drawn Circuits v3*, Roboflow *Electronic Circuit v8*, *SolvaDataset_200_v3* (hand-drawn symbols) |
| Training v1 | 100 epochs, imgsz 640, batch 8, lr0 0.01 |
| Training v2 | Fine-tuned from v1 on a Kaggle GPU: 60 epochs, batch 16, lr0 0.001, 10 backbone layers frozen |

**Classes (v2):** AC Source, Battery, Capacitor, Diode, Ground, Inductor, Resistor, Voltage, Dep. Voltage.

> Note: `README.md` and `BACKEND_SUMMARY.md` say the backend uses `circuit_detector_v2_best.pt`, but `recognizer.py:31` currently defaults to `circuit_detector_best.pt` (v1). The v2 line is commented out. Set `CIRCUIT_MODEL_WEIGHTS` to choose explicitly.

### 3.2 OCR models (optional)

| Model | Purpose |
|---|---|
| **easyocr** (English, CPU) with the **CRAFT** text detector | Finds and reads value labels and designators |
| **CRAFT exported to ONNX** (onnxruntime) | Faster text detection. Turn it off with `VALUE_OCR_ONNX=0` |
| **TrOCR**: `microsoft/trocr-small-handwritten` (Hugging Face, ~250 MB) | Second reader for handwriting. Turn it off with `VALUE_OCR_TROCR=0` |

### 3.3 Classical computer-vision techniques

Grayscale conversion, Gaussian blur, Otsu and adaptive thresholding, morphological close/dilate/erode, skeletonisation, connected-component labelling, distance transform, convex-polygon intersection (box merging), affine rotation, and net clustering.

### 4.6 User features

- Place parts from the palette, wire them, and edit properties
- **Draw Circuit**: sketch by hand, then **Generate Circuit** (AI recognition)
- **Load Image**: recognise a photo or scan of a circuit
- **Load Netlist**: import JSON
- **Simulate** with ngspice, then view node voltages, branch currents, current-flow arrows and branch analysis
- Toggle between the SVG schematic view and the interactive CircuitJS view
- Clean-UI toggle and wire colours

## 6. Data formats

| Format | Used for |
|---|---|
| **Netlist JSON (frontend to `/simulate`)** | `{ version, components[{id, ref, type, nodes, params}], nets }` plus `analysis` |
| **Recognition JSON (`/generate-circuit` to frontend)** | `title, timestamp, image, grid, nets, components, component_details, wires, dropped_detections` |
| **SPICE deck (`.cir`)** | Temporary file passed to ngspice |
| **CircuitJS text** | URL-encoded circuit for the Falstad embed |
| **Images** | PNG / JPEG as base64 or a data URL. Transparency is flattened onto white |
